# Iteration 19 — LLM 与工作流真实接入及第二用户闭环关闭 — Closed Loop

## 1. 配置入口

用户从“设置”进入全局执行配置：

```text
LLM 配置
→ 工作流连接
→ 工作流配置
```

项目内从“设置 → 工作流绑定”配置四个生产环节。

## 2. LLM Provider 闭环

```text
新增或编辑 OpenAI-compatible Provider
→ 填写 Base URL、API Key、超时和默认模型
→ 验证连接
→ 获取或校验模型列表
→ 选择默认模型
→ 启用 Provider
→ 成为工作流可选择的 LLM 执行依赖
```

规则：

- 未验证或验证失败的 Provider 不可用于新的工作流运行；
- API Key 不回显；
- 修改连接地址、密钥或关键参数后必须重新验证；
- 启用状态必须与最后验证结果一致；
- 运行记录只保存 Provider ID、版本、模型和安全元数据。

## 3. n8n 连接闭环

```text
新增或编辑 n8n 连接
→ 填写 Base URL、认证方式和凭据
→ 验证 n8n 服务
→ 验证成功
→ 启用连接
→ 成为工作流配置可选择的执行连接
```

规则：

- 未验证、验证失败或停用的连接不可用于工作流运行；
- 修改连接地址或凭据后必须重新验证；
- 前端不得看到认证凭据；
- 验证失败保留安全错误和修复入口。

## 4. 工作流配置闭环

```text
新增或编辑工作流配置
→ 选择已验证并启用的 n8n 连接
→ 配置 Workflow ID 或 Webhook Path
→ 选择适用环节
→ 配置输入、输出契约版本和默认参数
→ 明确 LLM 使用策略
→ 验证工作流引用和契约
→ 启用工作流
```

LLM 使用策略必须是以下之一：

1. 使用 ACF 管理的 LLM Provider 与模型；
2. 由 n8n 工作流内部管理 LLM；
3. 当前工作流不需要 LLM。

工作流列表和详情必须能识别其 LLM 使用策略，不允许出现来源不明的 LLM 调用。

## 5. 项目绑定闭环

```text
进入项目设置
→ 打开工作流绑定
→ 为章节规划、正文生成、审核、重写分别选择可用工作流
→ 保存绑定
→ 刷新后从真实 API 恢复绑定
```

可选工作流必须满足：

- 连接已验证并启用；
- 工作流已验证并启用；
- 适用环节匹配；
- LLM 使用策略完整；
- 输入和输出契约兼容。

## 6. 真实运行闭环

### 6.1 章节规划

```text
生成参数
→ 无副作用预检
→ 创建 WorkflowRun
→ n8n 执行工作流
→ 按冻结策略调用 LLM
→ 输出 Schema 校验
→ 创建候选批次
→ 用户采用并确认章节
```

### 6.2 正文生成

```text
选择已确认章节
→ 创建 WorkflowRun
→ n8n 与 LLM 真实执行
→ 输出 Schema 校验
→ 创建新 ContentVersion
→ 用户查看和编辑
```

### 6.3 内容审核

```text
选择固定 ContentVersion
→ 创建 WorkflowRun
→ n8n 与 LLM 真实执行
→ 输出 Schema 校验
→ 写入 ReviewReport、Findings 和 Recommendations
→ 用户处理审核问题
```

### 6.4 内容重写

```text
选择审核问题和重写要求
→ 创建 WorkflowRun
→ n8n 与 LLM 真实执行
→ 输出 Schema 校验
→ 创建新的 ContentVersion
→ 用户比较并采用
```

## 7. 运行追踪闭环

流程中心必须支持：

- 排队中；
- 运行中；
- 已成功；
- 已失败；
- 取消中；
- 已取消；
- 超时；
- 输出校验失败；
- 结果消费失败；
- 重试和重新执行；
- 页面刷新后恢复；
- 查看所使用的工作流、连接、LLM Provider、模型和配置版本。

不得展示：

- API Key；
- n8n Credential；
- Authorization Header；
- 完整上游敏感响应。

## 8. 异常闭环

- LLM 未验证、停用或模型失效：阻止发起并引导到 LLM 配置；
- n8n 连接未验证或停用：阻止发起并引导到连接配置；
- 工作流未验证、停用或引用失效：阻止发起并引导到工作流配置；
- 工作流 LLM 策略不完整：阻止启用和项目绑定；
- 项目未绑定：阻止业务运行并引导到项目设置；
- 外部执行失败：保留 WorkflowRun、安全错误和重试入口；
- 输出 Schema 非法：不写领域结果；
- 领域事务失败：整体回滚，不保存部分结果；
- 页面刷新：从 WorkflowRun 和领域结果恢复状态；
- 重试：创建新的运行记录，保留原运行和追踪链。
